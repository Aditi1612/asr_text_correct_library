asr_text_correct

애플리케이션 내에서 바로 동작하는 한국어 음성 인식(fine-tuned Whisper large-v3) + Gemini 전사 교정 라이브러리, 준실시간 스트리밍 지원.

GitHub: github.com/Aditi1612/asr_text_correct_library  ·  모델: huggingface.co/fluffy16/whisper-ko-asr (승인제)  ·  v0.1.0

개요

한국어 ASR 모델을 애플리케이션 프로세스 안에서 직접 실행하는 Python 라이브러리입니다. HTTP 서버도, 파이프라인 API 호출도 필요 없습니다. 모델을 한 번만 로드한 뒤 함수를 호출하면 됩니다. 전사 결과는 이어서 Google Gemini로 전달되어 잘못 인식된 음절, 띄어쓰기, 문법이 교정됩니다.

오디오 → Whisper (파인튜닝, 한국어) → 전사 + 신뢰도 → Gemini → corrected_text

  • 단건(one-shot): 오디오 파일이나 파형을 넘기면 원본 전사와 교정된 텍스트를 함께 돌려줍니다.
  • 스트리밍: 마이크 프레임을 계속 밀어 넣으면, 화자가 말을 멈출 때마다 방금 말한 발화의 교정된 전사를 반환합니다.
  • 한쪽만 사용: 음성 인식만(Gemini 키 불필요), 또는 교정만(모델 다운로드 불필요) 사용할 수도 있습니다.

디코딩과 교정 경로는 운영 파이프라인 코드를 그대로 옮긴 것입니다. 생성 설정, 텍스트 정규화, 반복 출력 필터, 교정 프롬프트, Gemini 키 순환이 모두 같습니다. 전사는 빠른 greedy 디코딩을 사용하며 GPU 메모리는 약 4 GB가 필요합니다.

시작하기 전에: 두 가지 접근 권한

항목이유받는 방법
모델에 대한 Hugging Face 접근 권한 모델 저장소는 승인제(gated)입니다. 승인된 계정만 가중치를 다운로드할 수 있습니다.
  1. huggingface.co에 로그인한 뒤 fluffy16/whisper-ko-asr를 엽니다.
  2. Request access를 클릭합니다. 관리자가 이미 계정을 추가해 둔 경우에는 이 단계를 건너뜁니다.
  3. 승인을 기다립니다.
  4. huggingface.co/settings/tokens에서 Read 토큰을 만듭니다.
Gemini API 키 교정 단계에서 Google Gemini API를 호출합니다. aistudio.google.com/apikey에서 키를 만들거나(무료 등급 있음), 관리자에게 요청하세요.
HF 토큰과 Gemini 키는 비밀번호처럼 다루세요. git에 커밋하거나 공유 문서에 붙여 넣지 말고, 아래처럼 환경 변수로 설정하세요.

빠른 시작 — 음성 인식 + 교정

from asr_text_correct import ASRCorrector

pipe = ASRCorrector(hf_repo="fluffy16/whisper-ko-asr")   # 최초 실행 시 약 6 GB 다운로드, 이후 캐시

r = pipe.process("clip.wav")
r.transcript        # '나는 바지를 입고 단추를 채웁니다'    음성 인식 원본 출력
r.corrected_text    # '나는 바지를 입고 단추를 채웠다.'      Gemini 교정 후
r.confidence        # 0.899   음성 인식 신뢰도, 0..1
r.is_uncertain      # False   신뢰도 < 0.15 이거나 전사가 비어 있으면 True
r.correction_ok     # True    Gemini가 실패해 대체 처리를 썼으면 False
r.timings           # {'stt': 0.2, 'text_correction': 0.77, 'total': 0.97}
r.to_dict()         # 위 내용 전체를 일반 dict로 (JSON 직렬화 가능)

process()는 입력으로 파일 경로, 인코딩된 바이트(wav/flac/ogg, ffmpeg가 있으면 mp3/m4a도 가능), 또는 input_sr=과 함께 전달한 numpy / torch 파형을 받습니다.

인자기본값의미
language"korean"Whisper 언어. "KR", "EN" 같은 코드도 가능
confidence_floor0.15신뢰도가 이 값보다 낮으면 is_uncertain이 True가 됨
reference_text—정답 전사. 전달하면 r.cer(문자 오류율)이 채워짐
prompt내장 프롬프트이번 호출의 교정 지시문을 대체

한쪽만 사용하기

from asr_text_correct import Transcriber, GeminiCorrector

# 음성 인식만: Gemini 키 불필요
asr = Transcriber(hf_repo="fluffy16/whisper-ko-asr")
asr.transcribe("clip.wav")                    # -> str
asr.transcribe("clip.wav", detailed=True)     # -> confidence / is_uncertain 포함 dict

# 교정만: 모델 다운로드 없이 Gemini 키만 필요
fix = GeminiCorrector()
fix.correct("은 변원 앞에 있어요 약을 하우레 두 씩 드세요")
# -> '병원 앞에 있어요. 약을 하루에 두 시 씩 드세요.'

# 이미 만든 객체를 조합
pipe = ASRCorrector(transcriber=asr, corrector=fix)

스트리밍 (준실시간)

애플리케이션이 어디서든 오디오를 캡처해 길이에 상관없이 mono float32 청크로 밀어 넣습니다. 화자가 말을 멈추면 그때까지 버퍼링된 발화가 전사·교정되어 반환됩니다. 부분 결과(partial)는 없으며, 발화마다 완성된 전사 하나가 제공됩니다. 

from asr_text_correct import ASRCorrector

pipe = ASRCorrector(hf_repo="fluffy16/whisper-ko-asr")
stream = pipe.stream(on_segment=lambda s: print(s.text, "->", s.corrected_text))

for chunk in your_mic_source():                       # 예: 20~100 ms 블록, 샘플레이트 무관
    for seg in stream.accept(chunk, input_sr=48000):  # 필요 시 내부에서 리샘플링
        handle(seg.corrected_text, seg.start_time, seg.end_time)

stream.flush()                                        # 스트림 종료 시 남은 발화를 마무리 처리
  • accept()는 확정된 Segment 목록을 반환합니다. 보통은 비어 있고, 발화가 막 끝났을 때 하나가 담깁니다. 각 세그먼트에는 .text(음성 인식 원본), .corrected_text, .start_time, .end_time이 있습니다.
  • pipe.stream(correct=False)로 만들면 Gemini를 건너뛰며, corrected_text는 None이 됩니다.
  • 발화가 끝나면 음성 인식과 Gemini 호출이 실행되는 동안 accept()가 블로킹됩니다(GPU 기준 보통 1~2초). 오디오 캡처 스레드가 멈추면 안 된다면, 큐를 두고 별도 워커 스레드에서 accept()를 호출하세요.
  • 실행 가능한 마이크 데모: examples/stream_mic.py

Gemini 설정

설정방법
API 키export GEMINI_API_KEY=...  또는  ASRCorrector(api_key="...")
여러 키 (순환)export GEMINI_API_KEYS=key1,key2,key3  또는  api_keys=[...]. 요청이 키들 사이에서 순환하며, 사용량 제한(429)에 걸리거나 실패한 키는 자동으로 건너뜁니다.

사용자 지시문ASRCorrector(prompt="...") 또는 process(..., prompt="..."). 라이브러리가 지시문 뒤에 원본 전사를 붙여 보냅니다.
Gemini가 실패해도(잘못된 키, 사용량 소진, 네트워크 없음) 결과는 반환됩니다. corrected_text에는 여분의 공백만 정리한 원본 전사가 들어가고 correction_ok는 False가 되므로, 교정이 중요하다면 이 값을 확인하세요. 대신 예외를 받고 싶다면 GeminiCorrector(fallback=False)를 사용하세요.

성능 (원래 서버에서 측정)

모델이 이미 로드된 상태에서 음성 인식 호출만 측정한 시간입니다. Gemini 교정은 네트워크에 따라 호출당 약 0.5~1초가 추가됩니다.

오디오 길이GPU (CUDA, fp16)CPU (48코어)
3.1 초0.20 초4.1 초
5.1 초0.26 초5.1 초
6.6 초0.25 초4.6 초
  • GPU: 짧은 클립당 약 0.2~0.3초. GPU 메모리는 최대 약 3.9 GB (모델 자체 3.1 GB).
  • CPU: 짧은 클립당 약 4~5초로 GPU보다 약 20배 느립니다. 가끔 파일을 처리하는 용도로는 쓸 만하지만 실시간 스트리밍에는 너무 느립니다.
  • 모델 로드: 처음 시작할 때 디스크에서 약 10초, 이후 OS가 파일을 캐시하면 1~5초.
  • Hugging Face 최초 다운로드: 약 6.2 GB. 시간은 네트워크에 따라 다르며(원래 서버 기준 약 50초), 이후에는 캐시가 유지됩니다.
  • 측정은 공유 서버에서 했습니다. 다른 작업으로 바쁜 GPU에서는 몇 배 느려질 수 있습니다.

제약 사항

  • 교정은 AI가 문장을 다시 쓰는 방식입니다. 어미나 시제를 바꾸거나 문장 부호를 추가할 수 있고, 가끔 잘못 추측하기도 합니다. 음성 인식 원문 그대로가 필요하면 r.transcript를 보관하세요.
  • 음성 인식 출력은 정규화되어 한글, 숫자, 공백만 남고 문장 부호는 없습니다. 모델이 같은 말을 반복하는 상태에 빠지면 전사는 빈 문자열("")로 반환되고 is_uncertain은 True가 됩니다.
  • 모든 Whisper 모델처럼, 순수한 잡음이나 침묵에서도 단어를 “들을” 수 있습니다. 샘플 세트에서 실제 음성은 신뢰도 0.88~0.91이었고, 3초짜리 잡음은 지어낸 단어를 신뢰도 0.20으로 출력했습니다. 기본 임계값 0.15보다 높아 불확실로 표시되지 않았습니다. 음성이 없는 오디오가 들어올 수 있다면 process(..., confidence_floor=0.5)처럼 임계값을 높이세요.
  • 모델은 발화 전체를 전사합니다. 단어 단위 실시간 출력은 없으며, “실시간”은 멈춤 직후 전사가 나타난다는 의미입니다.
  • 하나의 ASRCorrector는 한 번에 하나의 전사만 수행합니다. 병렬 처리가 필요하면 워커 프로세스마다 인스턴스를 하나씩 두세요.
  • 모델은 한국어 전용이며, 마비말·비정형 발화에 맞게 파인튜닝되어 있습니다.
  • 교정할 때마다 전사 텍스트가 Google Gemini API로 전송됩니다. 다루는 데이터에 대해 이것이 허용되는지 확인하세요.
